# Общие правила проекта `fyl`

Дата: 2026-03-25

## Назначение

Этот файл хранит общие правила разработки для репозитория `fyl`.
Здесь должны быть только универсальные правила проекта.
Частные решения по конкретным платам, модулям и прошивкам нужно держать в отдельных `Plan` или `docs` файлах.

## Общие правила по структуре

- проект держать в логике `PlatformIO`
- корневой build-файл: `platformio.ini`
- рабочий код держать в `src/`
- общие заголовки держать в `include/`, если они реально нужны
- переиспользуемые модули и библиотеки выносить в `lib/`, если это действительно оправдано
- тесты и проверочные заготовки держать в `test/`, если они есть
- ответственность по коду разносить по маленьким понятным модулям

## Общие правила по коду

- в начале каждого рабочего `.h` и `.cpp` файла писать короткий русский комментарий:
  - что делает файл
  - за что отвечает
  - его роль в проекте
- код писать минимальным и читаемым
- не раздувать файлы и модули без необходимости
- не тащить лишнюю legacy-логику без явной причины
- временные решения не превращать в постоянную архитектуру
- если функция сейчас не нужна проекту, не добавлять ее заранее

## Общие правила по секретам и локальным настройкам

- реальные секреты хранить только в локальных файлах, исключенных из git
- в репозитории держать только безопасные `.example`-шаблоны
- локальные настройки не должны становиться основой архитектуры проекта

## Общие правила по принятию решений

- сначала понять текущее состояние, потом чистить или переписывать
- сначала собрать минимальное рабочее ядро, потом расширять
- если можно написать проще, писать проще
- если код можно безопасно разделить на модули, лучше разделить
