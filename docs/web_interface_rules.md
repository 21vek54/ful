# Правила разработки веб-интерфейса

Дата: 2026-03-26

## Назначение

Этот документ задаёт короткие правила для операторских экранов проекта `fyl`.
Сейчас основной веб-интерфейс проекта живёт в `Node-RED` и `FlowFuse Dashboard`.

## Основные правила

- Перед правками читать `PLSN.md`, связанный файл в `Plan/` и этот документ.
- Для текущего dashboard править `infra/node-red/userdir/flows.json`.
- Все видимые пользователю подписи делать по возможности на русском.
- Английские термины оставлять только там, где они реально нужны:
  - `MQTT`
  - `Wi-Fi`
  - `I2C`

## Правило по кодировке

- `flows.json` и связанные markdown-файлы хранить в `UTF-8`.
- Если консоль показывает кракозябры, не доверять только терминалу.
- После правки проверять сам файл как `UTF-8` и отдельно проверять live runtime.
- Если вместо русских слов появились повторяющиеся знаки вопроса, файл считается сломанным.

## Обязательная проверка после правки

- `flows.json` валиден как JSON.
- В текстовых полях нет сломанной кириллицы.
- `Node-RED` успешно поднялся после изменений.
- Страница dashboard открывается.
- Живые данные реально обновляют экран.

## Правила экрана

- Оператор должен сразу видеть:
  - что живо
  - что не живо
  - когда было последнее обновление
- Для `version_5` оператор должен отдельно видеть pause-mode линии:
  - `перевод в паузу`
  - `пауза: удержание`
  - `пауза: линия пуста`
  - `требует восстановления`
- Для `version_5` оператор должен видеть counts:
  - сколько контейнеров осталось на запайщике
  - сколько контейнеров осталось в буфере двухручейкового подвода
- Для `version_5` оператор должен видеть, валидны ли counts и насколько они свежие
- Главные статусы ставить в верхнюю часть страницы.
- Платы показывать карточками, а не длинным списком.
- Цвет использовать только вместе с текстом:
  - `В сети`
  - `Нет связи`
  - `Нет данных`
- Диагностику держать в отдельном блоке простым языком.
- Нельзя подписывать `пауза` как `линия пуста`, если counts это не подтверждают.
- Нельзя подтверждать `pause_hold` или `pause_empty` на экране, если counts stale / invalid.

## Для будущих агентов

- Не считать сломанную кириллицу нормой отображения.
- Не ограничиваться проверкой в браузере: смотреть и файл, и runtime.
- Если меняется логика или стиль интерфейса, обновлять этот документ вместе с `flows.json`.
- Если меняется pause-контракт, обновлять этот документ вместе с операторской моделью статусов и текущим файлом плана.
