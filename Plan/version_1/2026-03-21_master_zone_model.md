# Модель зон и тарелок для мастера

## Назначение документа
Этот документ описывает, какие именно состояния линии должен хранить мастер, чтобы:
- видеть, где находятся тарелки;
- собирать общий цикл на понятной модели;
- восстанавливаться после аварии через подтверждение оператора.

## Главный принцип
Мастер должен хранить не только `состояние устройств`, но и `состояние продукта`.

То есть мастер должен понимать:
- где сейчас находятся тарелки;
- сколько их в ключевых зонах;
- какие участки заняты;
- можно ли безопасно продолжать общий цикл.

Графический интерфейс при этом находится не на мастере, а в `Node-RED` на этой машине.
Мастер только хранит модель, публикует ее и принимает корректировки от оператора.

## Два уровня модели

### 1. Предполагаемая модель
Это то, что мастер считает правильным на основе:
- предыдущих событий;
- завершенных шагов;
- статусов от конвейера;
- статусов от манипулятора;
- статуса запайщика.

### 2. Подтвержденная модель
Это то, что подтвердил оператор после аварии или нестандартной ситуации.

Именно подтвержденная модель должна использоваться как основа для продолжения общего цикла.

## Минимальная рабочая модель
Если делать практично и без перегруза, для первого этапа мастеру достаточно хранить такие зоны.

### Зона 1. Позиционная зона одноручейкового подводного
Что нужно знать:
- `0 тарелок`
- `1 тарелка`
- `2 тарелки`

Переменная:
- количество тарелок в позиционной зоне (`infeed_pos_count`)

Тип:
- `0..2`, либо `неизвестно`

### Зона 2. Двухручейковый подводной конвейер
По пользовательской логике важно понимать, какие линии заняты.

Минимальная версия:
- левая линия занята
- правая линия занята

Переменные:
- занятость левой линии (`infeed_2lane_left_busy`)
- занятость правой линии (`infeed_2lane_right_busy`)

### Зона 3. Запайщик
Нужно знать технологическое состояние.

Переменная:
- состояние запайщика (`sealer_state`)

Состояния:
- `пусто`
- `загружен`
- `в цикле`
- `готов`
- `неизвестно`

### Зона 4. Двухручейковый отводной конвейер
Минимально так же, как на подводном.

Переменные:
- занятость левой линии (`outfeed_2lane_left_busy`)
- занятость правой линии (`outfeed_2lane_right_busy`)

### Зона 5. Основной отводной конвейер, зона съема/накопления
Нужно знать, есть ли там тарелки.

Переменная:
- наличие тарелок в зоне основного отвода (`outfeed_main_zone_has_plates`)

Состояния:
- `есть`
- `нет`
- `неизвестно`

## Рекомендуемая модель следующего уровня
Если потом понадобятся более точные сценарии восстановления, лучше уйти не к "линия занята", а к модели позиций блока.

### Подводной двухручейковый
Не просто `левый/правый занят`, а три транспортных позиции блока:
- позиция 1 (`slot1`)
- позиция 2 (`slot2`)
- позиция 3 (`slot3`)

Для каждой позиции:
- `пусто`
- `занято`
- `неизвестно`

### Отводной двухручейковый
Точно так же:
- позиция 1 (`slot1`)
- позиция 2 (`slot2`)
- позиция 3 (`slot3`)

Это лучше соответствует реальной задаче формирования и выгрузки блоков по 6 тарелок.

## Рекомендованная структура данных мастера

```cpp
enum class ZoneValueState : uint8_t {
    Unknown = 0,
    Empty = 1,
    Occupied = 2
};

enum class SlotState : uint8_t {
    Unknown = 0,
    Empty = 1,
    Occupied = 2
};

enum class SealerState : uint8_t {
    Unknown = 0,
    Empty = 1,
    Loaded = 2,
    Running = 3,
    Done = 4
};

struct TwoLaneSlots3 {
    SlotState slot1 = SlotState::Unknown;
    SlotState slot2 = SlotState::Unknown;
    SlotState slot3 = SlotState::Unknown;
};

struct LineProductState {
    uint8_t infeedPosCount = 255; // 0..2, 255 = неизвестно
    bool infeed2LeftBusy = false;
    bool infeed2RightBusy = false;
    bool outfeed2LeftBusy = false;
    bool outfeed2RightBusy = false;
    ZoneValueState outfeedMainZone = ZoneValueState::Unknown;
    SealerState sealer = SealerState::Unknown;

    // Рекомендуемый следующий уровень детализации
    TwoLaneSlots3 infeed2Slots;
    TwoLaneSlots3 outfeed2Slots;

    bool operatorConfirmed = false;
    uint32_t revision = 0;
};
```

## Как мастер должен использовать эту модель

### В обычной работе
Мастер обновляет модель на основе:
- событий цикла;
- статусов платы конвейера;
- статусов манипулятора;
- статусов запайщика.

### После аварии
Мастер делает следующее:
1. останавливает общий цикл;
2. собирает текущие статусы узлов;
3. строит предполагаемую картину по зонам;
4. показывает оператору: `по-моему сейчас здесь вот так`;
5. оператор соглашается или исправляет;
6. после подтверждения мастер принимает эту модель как активную.

Это полностью соответствует обсужденной логике.

## Что должен видеть оператор в интерфейсе
Оператор должен видеть не только `занят/готов`, а именно картину по тарелкам.

Этот интерфейс должен быть реализован в `Node-RED`, а не в прошивке мастера.

### Обязательный набор
- `позиционная зона подводного`: `0 / 1 / 2`
- `двухручейковый подводной`: занятость линий или позиций
- `запайщик`: пуст / загружен / цикл / готов
- `двухручейковый отводной`: занятость линий или позиций
- `основной отводной`: есть тарелки / нет тарелок

Если позже будет использована модель позиций блока, то для каждой позиции достаточно:
- `пусто`
- `занята`
- `неизвестно`

### Обязательные действия оператора
- подтвердить предложенную картину;
- изменить количество тарелок в зоне;
- отметить занятость линии/позиции;
- очистить зону;
- сбросить всю модель продукта в ноль.

## Команды мастера для работы с моделью
Для `Node-RED` и MQTT лучше сразу предусмотреть понятные команды.
Ниже имена команд оставлены техническими, чтобы их потом было удобно переносить в код:
- `LINESTATE SHOW`
- `LINESTATE CLEAR`
- `LINESTATE CONFIRM`
- `LINESTATE SET INFEED_POS <0|1|2>`
- `LINESTATE SET IN2 LEFT <0|1>`
- `LINESTATE SET IN2 RIGHT <0|1>`
- `LINESTATE SET OUT2 LEFT <0|1>`
- `LINESTATE SET OUT2 RIGHT <0|1>`
- `LINESTATE SET MAIN_OUT <0|1>`
- `LINESTATE SET SEAL <EMPTY|LOADED|RUNNING|DONE>`

## Что рекомендую делать в первой реализации
Чтобы не перегрузить систему сразу, я бы сделал по этапам.

### Этап 1
Сделать в мастере только:
- `infeed_pos_count`
- `infeed_2lane_left_busy`
- `infeed_2lane_right_busy`
- `sealer_state`
- `outfeed_2lane_left_busy`
- `outfeed_2lane_right_busy`
- `outfeed_main_zone_has_plates`
- предполагаемая / подтвержденная модель

### Этап 2
Добавить ручную коррекцию из интерфейса.

### Этап 3
Если понадобится больше точности, заменить модель `левая/правая линия занята` на полную модель `позиция 1 / позиция 2 / позиция 3`.

## Итог
Твоя идея правильная:
- мастер должен понимать, сколько и где тарелок;
- после аварии он должен предлагать картину;
- оператор должен иметь право её подтвердить или исправить.

Для первой рабочей версии не нужно пытаться сделать идеальную модель всей линии.
Достаточно сделать понятную, ручно-корректируемую модель зон, которую можно потом уточнять.
