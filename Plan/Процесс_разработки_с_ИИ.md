# Процесс разработки с ИИ

Дата: 2026-03-26

## Назначение

Этот документ фиксирует, как проект разрабатывается с помощью ИИ-агентов.
Он описывает роли агентов и порядок их работы.

Если при пере-реализации проекта меняется сам процесс работы, этот документ нужно дорабатывать вместе с планами.

## Базовые роли

### Архитектор

Архитектор отвечает за:
- постановку следующего этапа;
- формулировку архитектурных решений;
- выделение границ ответственности;
- перевод идей в планы, контекст и правила.

Архитектор не должен подменять собой реализацию и независимую проверку.

### Кодер

Кодер отвечает за:
- реализацию задач по плану;
- правки кода, flow, конфигов и документации;
- локальные проверки после изменений;
- аккуратное движение по согласованному плану.

Кодер не должен сам себе ставить окончательный статус "всё проверено", если это требует независимой оценки.

### Ревьюер

Ревьюер отвечает за независимую проверку:
- кода;
- runtime-поведения;
- соответствия плану;
- фактического выполнения этапа.

Ревьюер должен проверять по фактам, а не по обещаниям или пересказу.

## Базовый порядок работы

1. Архитектор фиксирует контекст и план.
2. Кодер реализует очередной этап.
3. Ревьюер независимо проверяет результат.
4. После ревью обновляются:
- план;
- статус этапа;
- при необходимости архитектурная основа;
- при необходимости правила разработки.

## Что важно соблюдать

- Не смешивать роли в один неразличимый поток.
- Не считать отчёт кодера полноценным ревью.
- Не менять архитектурные решения только внутри чата без фиксации в документах.
- Если меняется архитектура, сначала обновлять `Plan/Архитектурная_основа.md`.
- Если меняется сам процесс работы с агентами, обновлять этот файл.

## Когда использовать такую схему обязательно

Эта схема обязательна, когда:
- меняется архитектура;
- меняется MQTT-контракт;
- меняется модель линии;
- меняется операторский интерфейс;
- закрывается или переносится этап плана.
