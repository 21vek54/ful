# Эталонные сценарии 30, 33, 36

Дата: 2026-03-31

### Назначение

Этот файл нужен для одинаковой проверки модели на типовых сценариях.
Каждый сценарий должен быть описан одинаково и сравниваться по устойчивым состояниям.

## Общие допущения

Во всех сценариях ниже используем одинаковые предположения:

- стартуем с пустой линии
- ошибок нет
- пауза не нажата, если это не указано отдельно
- `OUT2` и `MAIN_OUT` успевают освобождаться и не создают лишней блокировки
- сравниваем только устойчивые состояния
- порядок тика логики такой:
  - `INFEED -> SHIFT -> IN2 -> MANIPULATOR -> SEALER -> OUT2 -> MAIN_OUT`

## Общий формат сценария

Для каждого сценария фиксируем:

- стартовый снимок
- последний важный переход
- конечное устойчивое состояние

В финальной таблице обязательно указывать:

- `INFEED`
- `SHIFT`
- `IN2`
- `MANIPULATOR`
- `SEALER`
- `OUT2`
- `MAIN_OUT`

## Сценарий `30`

### Краткий смысл

`30` тарелок это `5` полных блоков по `6` тарелок без остатка на подводящей стороне.

### Стартовый снимок

| Сущность | Состояние |
|---|---|
| `INFEED` | `BUFFER_COUNT = 0` |
| `SHIFT` | `HOME_Z` |
| `IN2` | `[0,0,0]` |
| `MANIPULATOR` | `IDLE` |
| `SEALER` | `EMPTY` |
| `OUT2` | `[0,0,0]` |
| `MAIN_OUT` | `EMPTY` |

### Последний важный переход

Последний важный переход это пятый рабочий цикл `MANIPULATOR`:

- новый блок `B5` переносится `IN2 -> SEALER`
- готовый блок `B4` переносится `SEALER -> OUT2`
- после этого `SEALER` начинает запайку `B5`
- `OUT2` и `MAIN_OUT` отводят `B4`

### Конечное устойчивое состояние

После завершения запайки `B5` и отвода `B4` линия приходит к такому устойчивому состоянию:

| Сущность | Состояние |
|---|---|
| `INFEED` | `BUFFER_COUNT = 0` |
| `SHIFT` | `HOME_Z` |
| `IN2` | `[0,0,0]` |
| `MANIPULATOR` | `IDLE` |
| `SEALER` | `DONE` |
| `OUT2` | `[0,0,0]` |
| `MAIN_OUT` | `EMPTY` |

### Что это означает

- подводящая сторона уже пуста
- последний запаянный блок еще лежит в `SEALER`
- без нового полного блока на `IN2` обычный цикл `MANIPULATOR` больше не стартует

### Если в этот момент нажать `PAUSE`

- отдельный выгрузочный цикл из `SEALER` обязателен
- после него линия должна прийти в `pause_stable_wait`

## Сценарий `33`

### Краткий смысл

`33` тарелки это:

- `5` полных блоков по `6` тарелок
- `1` дополнительная пара
- `1` одиночная тарелка в буфере

### Стартовый снимок

| Сущность | Состояние |
|---|---|
| `INFEED` | `BUFFER_COUNT = 0` |
| `SHIFT` | `HOME_Z` |
| `IN2` | `[0,0,0]` |
| `MANIPULATOR` | `IDLE` |
| `SEALER` | `EMPTY` |
| `OUT2` | `[0,0,0]` |
| `MAIN_OUT` | `EMPTY` |

### Последний важный переход

После завершения цикла с `B5` на подводящую сторону приходят тарелки `31` и `32`:

1. из них собирается одна пара
2. `SHIFT` переносит ее в `IN2.LINE1`
3. в этом же тике `IN2` имеет право сделать свой такт
4. устойчивое положение этой пары становится таким:
   - `IN2 = [0,1,0]`

Потом приходит тарелка `33`:

- `INFEED` становится `BUFFER_COUNT = 1`

После этого `SEALER` завершает запайку `B5`.

### Конечное устойчивое состояние

| Сущность | Состояние |
|---|---|
| `INFEED` | `BUFFER_COUNT = 1` |
| `SHIFT` | `HOME_Z` |
| `IN2` | `[0,1,0]` |
| `MANIPULATOR` | `IDLE` |
| `SEALER` | `DONE` |
| `OUT2` | `[0,0,0]` |
| `MAIN_OUT` | `EMPTY` |

### Что это означает

- в `SEALER` лежит готовый блок `B5`
- на подводящей стороне уже есть часть следующего блока
- до полного блока на `IN2` не хватает еще `3` тарелок

### Если в этот момент нажать `PAUSE`

- линия переходит в `pause_fill_last_block`
- оператору нужно показать сообщение: `добавьте еще 3 тарелки`
- отдельный выгрузочный цикл из `SEALER` пока не является финалом, потому что подводящая сторона еще не пуста
- после добора недостающих `3` тарелок линия должна:
  - собрать последний полный блок
  - выполнить рабочий цикл `MANIPULATOR`
  - дождаться завершения запайки
  - выполнить обязательный выгрузочный цикл
  - прийти в `pause_stable_wait`

## Сценарий `36`

- новый блок `B6` переносится `IN2 -> SEALER`
