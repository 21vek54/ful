### Шаг 2. Стабилизировать `SEAL DONE` на конвейере

Нужно:

- проверить проводку и состояние входа `DONE` на `COM10`;
- убедиться, что в покое нет бесконечного переключения `released/active`;
- если проблема не только в проводке, усилить фильтрацию или latch в коде, но без ослабления контракта `SEALER`;
- повторно проверить локальный `SEAL START` и завершение цикла.

Временный сервисный инструмент для этого шага:

- использовать уже добавленный стендовый режим автоэмуляции:
  - `SEAL EMU AUTO ON [delay_ms] [hold_ms]`
  - `SEAL EMU AUTO OFF`
  - `SEAL EMU STATUS`
- смысл режима:
  - он существует только как временный сервисный инструмент на время отладки;
  - он не подменяет `SEAL START`;
  - он подменяет только приход `DONE`, если группа `SEAL` уже реально вошла в `WaitDone`.
- ожидаемое поведение:
  - после реального `SEAL START` группа `SEAL` переходит в `WaitDone`;
  - если включен `SEAL EMU AUTO`, при каждом входе в `WaitDone` ставится отложенный synthetic `DONE`;
  - через `delay_ms` формируется synthetic `DONE active`;
  - через `hold_ms` этот synthetic `DONE` автоматически отпускается.
- ограничения:
  - режим нужен только для стенда без реального запайщика или для временной отладки;
  - он не должен трактоваться как финальная production-модель;
  - источником истины при его использовании остаются логи `COM10`, `SEAL STATUS`, `SEAL EMU STATUS` и `completion_seq`.

Оговорки по ревью этого инструмента:

- для текущей отладки `SEAL EMU AUTO` допустим к использованию;
- блокирующей логической дыры вида "гарантированный двойной `completionSeq` от эмуляции" в ревью не найдено;
- при этом есть короткое окно, где completion уже засчитан, `runState` уже `Idle`, а эффективный `DONE` еще удерживается synthetic hold;
- поэтому во время отладки нельзя считать один только `busy=0` достаточным доказательством, что `SEAL` уже полностью "чист";
- если используется эмуляция, источником истины считать:
  - Serial лог `COM10`
  - `SEAL STATUS`
  - `SEAL EMU STATUS`
  - `completion_seq`
- master по `I2C` не обязан различать physical и synthetic completion;
- пока физический `DONE` шумит, нельзя интерпретировать каждый скачок `completion_seq` без сверки с логом `COM10`.

Правило использования на текущий момент:

1. Сначала реальный `SEAL START`
2. Потом подтверждение, что группа реально вошла в `WaitDone`
3. Только после этого разрешен `SEAL EMU AUTO ON`
4. После стабилизации физического `DONE` весь сервисный инструмент `SEAL EMU *` должен быть удален из runtime

Критерий завершения шага:
- в покое вход `DONE` стабилен;
- на один реальный цикл приходится одно осмысленное завершение, а не поток ложных событий.

Критерий завершения шага:
