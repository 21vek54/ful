# Контракт паузы и инварианты

Дата: 2026-03-31

### Назначение

Этот файл фиксирует поведение линии после `pause_requested`.

## Составные условия

### `feed_side_empty = 1`

Составное условие:

- `BUFFER_COUNT = 0`
- `SHIFT = HOME_Z`
- `IN2.LINE1 = 0`
- `IN2.LINE2 = 0`
- `IN2.LINE3 = 0`

### `feed_side_collects_last_block = 1`

Составное условие:

- подводящая сторона еще не пуста
- полного блока на `IN2` еще нет

### `OUT2_free = 1`

Составное условие:

- `OUT2.LINE1 = 0`
- `OUT2.LINE2 = 0`
- `OUT2.LINE3 = 0`

## Состояния паузы

### `pause_requested`

Оператор подал команду паузы, но линия еще не пришла в итоговое устойчивое состояние.

Это входное намерение, а не итоговый снимок линии.

### `pause_fill_last_block`

Линия дособирает последний блок на подводящей стороне.

Правила:

- `INFEED`, `SHIFT` и `IN2` еще могут работать по обычным условиям
- если тарелок до полного блока не хватает, подвод продолжает работать
- оператору показывается сообщение: `добавьте еще N тарелок`
- после сборки полного блока разрешается нужный цикл `MANIPULATOR`
- после последней запайки разрешается еще один цикл выгрузки из `SEALER`
- после завершения обязательных действий линия должна перейти в `pause_stable_wait`

### `pause_stable_wait`

Итоговое устойчивое состояние паузы.

Правила:

- линия больше не запускает новых рабочих действий
- линия просто ждет оператора
- `SEALER` уже пуст
- `MANIPULATOR = IDLE`
- `SHIFT = HOME_Z`

## Переходы между состояниями паузы

### Переход `pause_requested -> pause_fill_last_block`

Выполняется, если на подводящей стороне уже есть часть последнего блока.

### Переход `pause_requested -> обязательная выгрузка из SEALER`

Выполняется, если одновременно:

- `feed_side_empty = 1`
- `SEALER = DONE`
- `OUT2_free = 1`

В этом случае новый блок уже не собираем.
Разрешаем только цикл выгрузки из `SEALER`.

### Переход в `pause_stable_wait`

Выполняется, когда:

- обязательные действия паузы уже завершены
- `SEALER = EMPTY`
- линия пришла в устойчивое состояние

## Разрешенные старты после `pause_requested`

### Еще разрешены

- `INFEED` — только если идет сборка последнего полного блока
- `SHIFT` — только если идет сборка последнего полного блока
- `IN2` — только если идет сборка последнего полного блока
- `MANIPULATOR` — только для завершения уже разрешенной логики паузы
- `SEALER` — только для последней уже разрешенной запайки
- `OUT2` — только для приема и отвода уже выпущенного блока
- `MAIN_OUT` — только для отвода уже выпущенного блока

### Уже запрещены

- старт нового обычного производственного цикла после достижения `pause_stable_wait`
- запуск новой запайки после того, как линия уже дошла до итоговой чистой паузы
- набор нового лишнего блока после завершения обязательной логики паузы

## Обязательный выгрузочный цикл

Если одновременно выполнены условия:

- подводящая сторона уже пуста
- `SEALER = DONE`
- `OUT2` свободен

то выгрузочный цикл обязателен.
После него линия должна прийти к состоянию, где `SEALER` пуст.

Если `OUT2` пока не свободен, линия сначала дожидается освобождения `OUT2`, а потом выполняет обязательную выгрузку.
Во время такого ожидания линия остается в `pause_requested` и не запускает новых обычных производственных стартов.

## Инварианты

Ниже правила записаны в почти кодовом виде.
Рядом дан русский комментарий.

- `IF pause_state = pause_stable_wait THEN SEALER = EMPTY`
  `# Чистая пауза допустима только с пустым запайщиком`

- `IF pause_state = pause_stable_wait THEN MANIPULATOR = IDLE`
  `# В итоговой паузе манипулятор уже не должен быть внутри рабочего цикла`

- `IF pause_state = pause_stable_wait THEN SHIFT = HOME_Z`
  `# В итоговой паузе SHIFT должен быть в исходном положении`

- `IF IN2.LINE1 = 0 THEN IN2 does not auto-tick`
  `# IN2 не крутится сам по себе с пустой первой позицией`

- `IF SHIFT writes pair to IN2.LINE1 in current logic tick THEN IN2 may auto-tick in the same logic tick`
  `# После записи пары в LINE1 накопитель может сдвинуться сразу в этом же тике`

- `IF SHIFT writes pair to IN2.LINE1 in current logic tick AND IN2.LINE3 = 1 after the write THEN IN2 does not auto-tick in the same logic tick`
  `# Если после записи уже получился полный блок, дополнительный сдвиг IN2 не нужен`

- `IF MANIPULATOR = IDLE AND SEALER = DONE AND OUT2_free = 1 AND pause_state <> pause_stable_wait AND feed_side_empty = 1 THEN unload cycle is mandatory`
  `# В паузе отдельный выгрузочный цикл обязателен, если подводящая сторона уже пуста`

- `IF pause_state = pause_requested AND feed_side_empty = 1 AND SEALER = DONE AND OUT2_free = 0 THEN line waits for OUT2 without new production starts`
  `# Пока OUT2 занят, линия ждет возможность обязательной выгрузки и не начинает новый обычный цикл`

- `IF pause_state = pause_stable_wait THEN new production starts are forbidden`
  `# В чистой паузе новые производственные старты уже запрещены`

- `IF pause_state = pause_fill_last_block THEN starts on INFEED, SHIFT and IN2 are allowed only by ordinary conditions`
  `# Во время добора последнего блока подводящая сторона работает не свободно, а только по своим обычным условиям`

- `IF MANIPULATOR ordinary start is allowed THEN full block on IN2 = 1`
  `# В обычном режиме манипулятор нельзя запускать без полного блока на IN2`

- `IF step7_ready = 1 THEN SEALER start may be considered without waiting step 8`
  `# Для ранней синхронизации можно ориентироваться на step7 ready, шаг 8 только возвращает каретку`

## Что этот файл не описывает

- recovery манипулятора
- низкоуровневый формат пакетов `I2C`
- внутренние микрошаги внутри `BUSY`, кроме тех, что уже нужны для логики паузы и синхронизации
