# Термины и снимки состояний

Дата: 2026-03-31

### Назначение

Этот файл фиксирует строгие термины `version_4`.
Его задача — убрать споры из-за разных значений слов `цикл`, `такт`, `шаг` и `состояние`.

## Правило общения

- Если формулировка в чате двоякая, ее нужно уточнять, а не додумывать.

## Приоритет для `version_4`

- Если старый базовый текст или текущая прошивка плат расходятся с зафиксированными терминами `version_4`, для архитектурной приемки `version_4` приоритет у документов внутри `Plan/version_4/`.
- Это значит, что при необходимости под `version_4` переписываем логику плат, а не ослабляем уже согласованную модель без отдельного решения.

## Термины

### `пара`

Две тарелки, которые линия рассматривает как одну транспортную единицу для `SHIFT`, `IN2` и `OUT2`.

### `блок`

Три пары, то есть `6` тарелок.

### `полный блок`

Блок, для которого одновременно выполнены условия:

- `LINE1 = 1`
- `LINE2 = 1`
- `LINE3 = 1`

### `такт IN2`

Один сдвиг накопителя `IN2` на одну позицию вперед.

### `цикл SHIFT`

Полный ход `SHIFT`:

- `HOME_Z -> BUSY -> SHIFTED_C -> BUSY -> HOME_Z`

### `рабочий цикл линии`

Общее неформальное название непрерывной работы линии.
В расчетах `version_4` этот термин не используем как вычислительный, чтобы не путать его с `циклом SHIFT` и `рабочим циклом MANIPULATOR`.

### `рабочий цикл MANIPULATOR`

Полная команда `R`.

### `шаг MANIPULATOR`

Один внутренний шаг внутри команды `R`.
Шаги нумеруются `1..8`.

### `тик логики`

Один проход логики контроллера верхнего уровня.

За один `тик логики` состояния проверяются и обновляются в таком порядке:

- `INFEED`
- `SHIFT`
- `IN2`
- `MANIPULATOR`
- `SEALER`
- `OUT2`
- `MAIN_OUT`

Это значит:

- более поздний узел в списке видит изменения, которые уже сделал более ранний узел в этом же тике
- более ранний узел не может в этом же тике повторно отреагировать на изменения, сделанные позже

## Снимки состояния

### `состояние до тика`

Устойчивый снимок перед началом очередного тика логики.

### `переходное состояние`

Временное состояние внутри тика логики после обновления одного или нескольких узлов.
Такое состояние можно использовать для объяснения механики, но не как главный эталон для споров.

### `состояние после тика`

Состояние после завершения всех разрешенных обновлений в текущем тике логики.

### `устойчивое состояние`

Состояние, в котором ни один узел не находится внутри движения, такта или незавершенного перехода.

Примеры:

- `SHIFT = HOME_Z`, `MANIPULATOR = IDLE`, `SEALER = DONE` — это устойчивое состояние
- `SHIFT = BUSY` или `MANIPULATOR = BUSY` — это уже не устойчивое состояние

## Составные понятия

### `подводящая сторона пуста`

Составное условие:

- `BUFFER_COUNT = 0`
- `SHIFT = HOME_Z`
- `IN2.LINE1 = 0`
- `IN2.LINE2 = 0`
- `IN2.LINE3 = 0`

### `подводящая сторона еще собирает последний блок`

Составное условие:

- на подводящей стороне уже есть хотя бы часть будущего блока
- но полного блока на `IN2` еще нет

Практически это значит, что выполняется хотя бы одно из условий:

- `BUFFER_COUNT > 0`
- `IN2.LINE1 = 1`
- `IN2.LINE2 = 1`
- `IN2.LINE3 = 1`

и при этом полный блок на `IN2` еще не собран.

## Важное правило для `IN2`

- Если `SHIFT` в текущем тике записал пару в `IN2.LINE1`, то `IN2` имеет право сделать свой такт в этом же тике логики.
- Если после записи пары уже получилось `IN2.LINE3 = 1`, то дополнительный такт `IN2` в этом же тике не происходит.

## Пример одного тика логики

Пусть состояние до тика такое:

- `BUFFER_COUNT = 2`
- `IN2.LINE1 = 0`
- `IN2.LINE2 = 1`
- `IN2.LINE3 = 0`

Тогда в этом же тике логики может произойти:

1. `SHIFT` переносит пару в `IN2.LINE1`
2. переходное состояние становится таким:
   - `BUFFER_COUNT = 0`
   - `IN2 = [1,1,0]`
3. потом `IN2` делает свой такт в этом же тике
4. состояние после тика становится таким:
   - `IN2 = [0,1,1]`

Этот пример нужен для того, чтобы не путать:

- `переходное состояние внутри тика`
- `итоговое состояние после тика`

## Как использовать снимки в документах

- Все эталонные примеры сравнивать только по устойчивым состояниям.
- Если нужно показать механику внутри тика, такой снимок обязательно помечать как переходный.
- Если в примере не написано, что это переходное состояние, по умолчанию считаем его устойчивым.
- При споре о состоянии сначала нужно уточнить, о каком снимке идет речь:
  - `до тика`
  - `переходное`
  - `после тика`
