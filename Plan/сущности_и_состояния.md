# Сущности и состояния

Дата: 2026-03-31

### Назначение

Этот файл — короткая сводка по сущностям линии и их текущим состояниям.
Для базовой логики цикла первичным остается `Plan/основной_цикл.md`.
Для пакета `version_4` уточнения по снимкам состояния, паузе и ранним признакам синхронизации берем из `Plan/version_4/`.

## Сущности линии

### `INFEED`

Что это:
подводящий участок, который собирает тарелки по одной и формирует пару.

Состояния:
- `BUFFER_COUNT = 0` — в буфере нет тарелок
- `BUFFER_COUNT = 1` — в буфере одна тарелка
- `BUFFER_COUNT = 2` — в буфере собрана пара

Важные правила:
- `INFEED` может поднять пневмофлаг только если `SHIFT = HOME_Z`

### `SHIFT`

Что это:
узел, который переносит пару с `INFEED` на `IN2`.

Состояния:
- `HOME_Z` — исходное состояние после `Z`, каретка в базовом положении
- `BUSY` — каретка в движении
- `SHIFTED_C` — каретка дошла до `C` и находится в сдвинутом рабочем положении

Нормальный цикл `SHIFT`:
- `HOME_Z -> BUSY -> SHIFTED_C -> BUSY -> HOME_Z`

Важно:
- состояние `BUSY` появляется два раза за полный цикл: при движении к `C` и при возврате к `Z`
- `INFEED` может работать с пневмофлагом только когда `SHIFT` находится в `HOME_Z`
- перенос пары в `IN2` начинаем только когда есть готовая пара на `INFEED` и `IN2.LINE1` свободна

### `IN2`

Что это:
подводящий накопитель перед манипулятором.

Состояния:
- отдельного общего состояния для всего `IN2` не вводим
- состояние `IN2` считаем по трём позициям:
- `IN2.LINE1`
- `IN2.LINE2`
- `IN2.LINE3`

Состояния каждой позиции:
- `0` — в позиции нет пары
- `1` — в позиции есть пара

Важно:
- полный блок на `IN2` означает, что `LINE1 = 1`, `LINE2 = 1` и `LINE3 = 1`
- если `LINE1` пуста, `IN2` сам по себе не крутится

### `MANIPULATOR`

Что это:
манипулятор с двумя синхронными блоками захватов по 6 тарелок.

Основные состояния:
- `IDLE` — манипулятор свободен
- `BUSY` — манипулятор выполняет рабочий цикл
- `ERROR` — манипулятор в ошибке

Дополнительно из прошивки:
- `current step = 0..8` — текущий шаг рабочего цикла
- `step7 ready = yes/no` — признак, что шаг 7 уже достигнут

Дополнительные флаги для логики линии:
- `step3_ready = 0/1` — целевой логический флаг верхнего уровня: правая сторона уже освобождена после шага 3, можно принимать решение по `IN2`
- `step7_ready = 0/1` — latch-признак из прошивки: после шага 7 левая сторона уже отработана, можно принимать решение по `SEALER` и `OUT2`

Важно:
- отдельного стабильного состояния `DONE` по `I2C` сейчас нет
- успешное завершение цикла считаем как переход из `BUSY` в `IDLE` без ошибки и с `current step = 0`
- `step7_ready` уже реально есть в текущей прошивке манипулятора и сейчас ведет себя как latch до старта следующего рабочего цикла
- `step3_ready` пока лучше считать логическим флагом верхнего уровня, а не готовым отдельным битом из прошивки
- по одному `current step` безопасно не считать `step3_ready` готовым runtime-сигналом
- если `version_4` потребует этот признак в коде, его нужно либо добавить в прошивку манипулятора, либо заменить более консервативным условием

### `SEALER`

Что это:
узел запайки.

Состояния:
- `EMPTY` — в запайщике нет блока
- `LOADED` — блок загружен, но цикл ещё не запущен
- `RUNNING` — идёт цикл запайки
- `DONE` — цикл запайки завершён

### `OUT2`

Что это:
отводящий накопитель после запайщика.

Состояния:
- отдельного общего состояния для всего `OUT2` не вводим
- состояние `OUT2` считаем по трём позициям:
- `OUT2.LINE1`
- `OUT2.LINE2`
- `OUT2.LINE3`

Состояния каждой позиции:
- `0` — в позиции нет пары
- `1` — в позиции есть пара

Важно:
- полный блок на `OUT2` означает, что `LINE1 = 1`, `LINE2 = 1` и `LINE3 = 1`
- в процессе отвода `OUT2` может быть частично заполнен

### `MAIN_OUT`

Что это:
основной отводной конвейер.

Состояния:
- `EMPTY` — в зоне отвода нет пары
- `OCCUPIED` — в зоне отвода есть пара
- `MOVING` — выполняется такт отвода

## Составные условия

Это не отдельные новые сущности, а просто полезные условия, которые считаем по уже существующим состояниям.

### Полный блок на `IN2`

- `IN2.LINE1 = 1`
- `IN2.LINE2 = 1`
- `IN2.LINE3 = 1`

### Полный блок на `OUT2`

- `OUT2.LINE1 = 1`
- `OUT2.LINE2 = 1`
- `OUT2.LINE3 = 1`

### Манипулятор готов к обычному рабочему циклу

- манипулятор не в `BUSY`
- манипулятор не в `ERROR`
- правый концевик нажат
- вертикаль поднята
- захват открыт

## Что пока не формализовано отдельным списком состояний

- общий режим линии пока не оформлен как отдельный enum
- пауза уже формализована в `Plan/version_4/2026-03-31_контракт_паузы_и_инварианты.md`, но еще не сведена обратно в отдельную общую таблицу состояний базового контура
- recovery манипулятора пока считаем отдельным сервисным сценарием, а не обычным состоянием линии
