## План minimal master v2

Дата: 2026-03-24

### Основная идея

`Master v2` должен стать тонким транспортным слоем:
- подключение к Wi-Fi
- подключение к MQTT
- публикация статуса устройства
- приём MQTT-команд
- выполнение только минимально необходимого мостика команд
- переподключение без перезагрузки ESP32

Бизнес-логика, операторские сценарии, последовательности действий и поведение интерфейса должны быть вынесены из прошивки в `Node-RED`.

### Что остаётся в мастере

- загрузка и сохранение параметров Wi-Fi
- загрузка и сохранение параметров MQTT
- периодические попытки переподключения
- подписка MQTT на командный топик
- публикация в топики статуса и ответа
- минимальный диспетчер команд
- serial-диагностика для наладки и сервиса

### Что должно уйти из мастера

- крупная сценарная логика
- логика оркестрации
- поведение, завязанное на UI
- высокоуровневые производственные решения
- композиция потоков, которую можно перенести в Node-RED

### Жёсткое правило

Не перезагружать плату для восстановления Wi-Fi или MQTT.

Модель восстановления:
- обнаружить разрыв соединения
- не останавливать основной цикл
- повторять подключение к Wi-Fi по таймеру
- после восстановления Wi-Fi повторять подключение к MQTT по таймеру
- не блокировать локальный цикл длинными ожиданиями

### Роль Node-RED в v2

`Node-RED` должен стать координатором верхнего уровня:
- отправлять команды в `cmd`
- слушать `status`, `resp`, `event`
- держать dashboard и операторские действия
- реализовывать цепочки сценариев
- хранить высокоуровневую логику вне прошивки

### Объём сброса для чистой пересборки

Цель сброса Node-RED:
- сохранить резервные копии текущих flows
- сбросить рабочий `flows.json`
- при необходимости сбросить вспомогательные runtime/credential-файлы
- стартовать с пустого или почти пустого набора flows

Цель сброса Mosquitto:
- подтвердить, какой конфиг реально использует служба
- безопасно остановить службу
- заменить активный конфиг на минимальный чистый вариант
- заново запустить службу
- осознанно проверить порт прослушивания и режим `anonymous/auth`

### Безопасный порядок выполнения

1. Зафиксировать планы и инвентаризацию `version_1`.
2. Сделать резервную копию живого состояния `Node-RED` и `Mosquitto`.
3. Подтвердить путь к активному конфигу `Mosquitto`.
4. Сбросить `Node-RED` к минимальному состоянию.
5. Сбросить `Mosquitto` к минимальному состоянию.
6. Перестроить `master_control_com12` в минимальный транспорт `Wi-Fi + MQTT`.
7. Поверх чистого транспорта заново собрать flows в `Node-RED`.
