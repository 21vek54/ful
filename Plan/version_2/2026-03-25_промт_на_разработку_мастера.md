- `C:\Users\Пользователь\Documents\PlatformIO\Projects\fyl\firmware\master_control_com12`

Важное правило:
старый `master` использовать только как архивный донор проверенных фрагментов.
Не возвращать старую архитектуру целиком и не лечить старый монолит как основную базу.

Цель нового `master_control_com12` на текущем этапе:
- инициализировать самого себя при старте
- поднять `Wi-Fi`
- поднять `MQTT`
- опрашивать по `I2C` только платы `12` и `13`
- определять для них только состояние `online / offline`
- публиковать это состояние в `MQTT`

Что уже известно и нужно сохранить:
- `I2C SDA = 21`
- `I2C SCL = 22`
- `I2C id conveyor = 12`
- `I2C id manipulator = 13`
- базовый MQTT topic: `fyl/master_com12`

Что нельзя возвращать без отдельного решения:
- `RS485`
- `Modbus`
- `VFD`
- `SEAL`
- `COMMON cycle`
- `OTCYCLE`
- большой сервисный `CLI`
- старую оркестрацию верхнего уровня

Требования к разработке:
- соблюдать общие правила из `PLSN.md`
- держать проект в логике `PlatformIO`
- `platformio.ini` оставлять корневым build-файлом проекта
- рабочий код держать в `src/`
- общие заголовки держать в `include/`, только если это реально нужно
- разносить код по маленьким понятным модулям
- в начале каждого рабочего `.h` и `.cpp` файла писать короткий русский комментарий:
  - что делает файл
  - за что отвечает
  - его роль в проекте
- код писать минимальным и читаемым
- реальные секреты хранить только в локальных файлах:
  - `src/wifi_secrets_local.h`
  - `src/mqtt_secrets_local.h`
- в репозитории хранить только `.example` шаблоны

Ожидаемый подход к работе:
- сначала понять текущее состояние нового проекта
- затем предложить или сразу собрать чистую модульную структуру
- переносить из архива только реально нужные куски
- после каждого заметного изменения проверять сборку через `pio run`
- не оставлять проект в частично сломанном состоянии

Предпочтительное направление разбиения:
- `src/main.cpp`
- `src/core/`
- `src/net/`
- `src/comm/`

Минимально ожидаемые модули:
- запуск и главный цикл
- `Wi-Fi` менеджер
- `MQTT` менеджер
- `I2C` poller для плат `12` и `13`
- простая модель состояния устройства

Критерий готовности ближайшего этапа:
- проект собирается через `pio run`
- код не является монолитом
- есть отдельные модули для `Wi-Fi`, `MQTT` и `I2C`
- публикуется понятный MQTT-статус по платам `12` и `13`
- структура и комментарии соответствуют `PLSN.md`
