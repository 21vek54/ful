## Этап 1. Инвентаризация текущего `master_control_com12`

Дата: 2026-03-25

Источник разбора:
- `firmware/master_control_com12`

Уточнение цели:
- Под минимальный `master` теперь принимается очень узкая роль:
  - инициализировать самого себя при старте
  - подключиться к `Wi-Fi`
  - подключиться к `MQTT`
  - по `I2C` опрашивать только две платы: `12` и `13`
  - определять только факт `онлайн / офлайн`
  - публиковать это состояние в `MQTT`
- Под `i2s` в этом документе трактую именно `I2C`, потому что текущий `master_control_com12` работает с двумя платами по `I2C`, а не по `I2S`.

Краткий вывод:
- Проект физически небольшой, но логически сильно перегружен: почти всё собрано в одном файле `src/master_main.cpp`.
- Для новой минимальной цели большая часть текущего `master` не нужна.
- Нужное ядро уже читается в проекте:
  - базовая self-init логика master при старте
  - `Wi-Fi`
  - `MQTT`
  - `I2C`-опрос managed-device плат
  - базовый `setup()/loop()`
- Лишнее для нового минимального варианта:
  - `RS485 / Modbus / VFD`
  - `SEAL`
  - `COMMON cycle`
  - `OTCYCLE`
  - большая часть CLI и сервисной отладки
- Проверка `pio run` на 2026-03-25 проходит успешно: RAM `15.2%` (`49960 / 327680`), Flash `77.4%` (`1014364 / 1310720`).

Принятые границы инвентаризации:
- В отчёт включены только корень проекта, `.vscode`, `docs`, `shortcuts`, `src`.
- Build-папка `.pio/` физически присутствует после сборки, но в инвентаризацию не включена как временный артефакт.

### Срезы по подсистемам

#### Сетевой слой

- Реально присутствует:
  - `wifiLoadCredentials()`
  - `wifiSaveCredentials()`
  - `wifiClearCredentials()`
  - `wifiTryConnect()`
  - `wifiTryAutoConnect()`
  - `wifiPrintStatus()`
  - `handleCommandWifi()`
- Для новой цели нужен только минимальный Wi-Fi:
  - загрузить параметры
  - подключиться
  - переподключаться при обрыве
- Необязательное для новой цели:
  - serial prompt
  - лишние ручные команды

Вывод:
- Wi-Fi слой оставить
- блокирующий prompt и богатый CLI лучше убрать

#### MQTT-часть

- Реально присутствует:
  - загрузка и сохранение MQTT настроек
  - topic map
  - reconnect loop
  - публикация статуса
  - command bridge через `handleConsoleLine()`
- Для новой цели нужен только простой выход в MQTT:
  - публиковать онлайн-статус плат `12` и `13`
  - при желании публиковать состояние Wi-Fi / MQTT
- Необязательное для новой цели:
  - общий command bridge
  - подробный широкий JSON статуса
  - ответы на сервисные команды

Вывод:
- MQTT оставить
- payload и логику приёма команд сильно упростить

#### Бизнес-логика

- По новой цели бизнес-логика должна стать почти пустой.
- Нужное поведение:
  - инициализировать самого себя при старте
  - опросить `I2C` плату `12`
  - опросить `I2C` плату `13`
  - определить `online / offline`
  - отдать это в `MQTT`
- Всё остальное для этой цели лишнее:
  - `SEAL`
  - `COMMON cycle`
  - `OTCYCLE`
  - сценарии VFD
  - сложная интерпретация статусов conveyor/manipulator

Вывод:
- новая целевая логика `master` очень узкая и не требует старых производственных сценариев

#### Временный и сервисный код

- С точки зрения новой цели лишними становятся:
  - `wifiPromptAndConnect()`
  - `findVfdOnCommonUartSettings()`
  - `VFD SETUPRS`
  - `MBRAW`
  - `RS <text>`
  - `RSPING <id>`
  - `MBSCAN NOW`, `MBSCAN RANGE`
  - ручные `VFD START/STOP/FREQ/...`
  - тестовые `RUN5`, `RUN5MIN`, `RUNCM`, `CYCLE30`
- Это не значит, что код плохой сам по себе.
- Это значит только одно: он не нужен для нового узкого профиля `master`.

Вывод:
- сервисный и наладочный слой теперь не ядро, а лишний хвост

#### Дубли и legacy

- В коде одновременно есть:
  - `processOtvodWorkCycle()`
  - `processOtvodWorkCycleStrict()`
- В `OtvodWorkCycleState` остаются legacy-поля:
  - `stepTriggerIssued`
  - `vfdTriggerIssued`
- В CLI остался legacy-аргумент `cm_legacy`

Вывод:
- дубли и legacy по `OTCYCLE` теперь точно не нужны

#### Спорные куски

- Один файл `master_main.cpp` держит всё сразу:
  - Wi-Fi
  - MQTT
  - I2C
  - RS485
  - CLI
  - диагностику
  - старые production-сценарии
- JSON собирается вручную через `String`
- реальные локальные секреты лежат в `src/`
- command router смешивает сервис, отладку и production-логику

Вывод:
- главная проблема теперь видна ещё яснее: цель очень маленькая, а код вокруг неё слишком большой
