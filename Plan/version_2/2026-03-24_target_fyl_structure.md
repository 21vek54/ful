## Целевая структура папки fyl

Дата: 2026-03-24

### Цель

Привести рабочую область `fyl` к понятной структуре, где:
- прошивки лежат отдельно
- инфраструктура `Node-RED` и `Mosquitto` лежит отдельно
- архивы и резервные копии не смешаны с кодом
- корень проекта остаётся читаемым

### Рекомендуемая структура

```text
fyl/
├─ firmware/
│  ├─ conveyor_control_com10/
│  ├─ manipulator_com11/
│  ├─ master_control_com12/
│  ├─ conveyor_control_com3/
│  └─ master_control_com9/
├─ testbench/
│  ├─ i2c_smoketest_3boards/
│  ├─ rs485_autodir_test/
│  ├─ spi_linecheck_3boards/
│  ├─ spi_smoketest_3boards/
│  └─ test_zapaika/
├─ infra/
│  ├─ node-red/
│  │  ├─ userdir/
│  │  ├─ backups/
│  │  └─ launch/
│  ├─ mosquitto/
│  │  ├─ conf/
│  │  ├─ data/
│  │  ├─ log/
│  │  └─ launch/
│  └─ mqtt/
│     └─ notes/
├─ archive/
│  ├─ flows/
│  ├─ exports/
│  └─ old_runtime/
├─ bin/
├─ Plan/
│  ├─ version_1/
│  └─ version_2/
├─ tools/
│  ├─ flash/
│  └─ service/
├─ .gitignore
└─ fyl.code-workspace
```

### Что должно лежать в каждом разделе

#### `firmware`

Здесь должны лежать только проекты прошивок PlatformIO:
- основные рабочие платы
- старые версии плат, если они ещё нужны для истории или поддержки

Из этих проектов нужно убрать инфраструктурные артефакты, не относящиеся к прошивке:
- выгрузки `Node-RED`
- резервные копии flows
- случайные runtime-файлы внешних сервисов

#### `testbench`

Здесь должны лежать стенды, эксперименты и технические тесты:
- проверки шин
- временные тестовые прошивки
- отладочные проекты

Для этой папки нормально иметь временный характер, но она не должна засорять корень.

#### `infra`

Это новый ключевой раздел для всей внешней инфраструктуры проекта.

##### `infra/node-red`

Здесь должен жить локальный экземпляр `Node-RED`, привязанный к проекту.

Рекомендуемое наполнение:
- `userdir/` для рабочих файлов `Node-RED`
- `backups/` для резервных копий `flows.json`
- `launch/` для bat/cmd/ps1-скриптов запуска

Внутри `userdir/` позже могут лежать:
- `flows.json`
- `flows_cred.json`
- `settings.js`
- `.config.nodes.json`
- `.config.runtime.json`
- `.config.users.json`

##### `infra/mosquitto`

Здесь должен жить проектный контур `Mosquitto`.

Рекомендуемое наполнение:
- `conf/` для активных конфигов
- `data/` для persistence при необходимости
- `log/` для логов
- `launch/` для скриптов запуска и обслуживания

Примечание:
- на первом этапе можно оставить сам установленный `mosquitto.exe` в `C:\Program Files\Mosquitto`
- при этом все рабочие конфиги и данные уже перенести в `fyl/infra/mosquitto`

##### `infra/mqtt`

Это не отдельный сервис, а место для описания MQTT-схемы:
- схема топиков
- правила публикации
- формат полезной нагрузки
- заметки по доступу и портам

#### `archive`

Сюда нужно убрать всё, что важно сохранить, но не нужно держать в рабочих папках:
- старые flow-экспорты
- ручные backup-файлы
- снимки runtime-состояния
- промежуточные выгрузки перед рефакторингом

В частности, сюда логично перенести:
- `_backup_flows_before_http_control.json`
- экспортированные `Node-RED` flows из `master_control_com12`

#### `tools`

Сюда нужно перенести служебные скрипты из корня:
- `flash_conveyor_com10.cmd`
- `flash_manipulator_com11.cmd`
- `flash_master_com12.cmd`

Рекомендуемое разбиение:
- `tools/flash/` для прошивки плат
- `tools/service/` для обслуживания `Node-RED`, `Mosquitto`, backup и диагностики

### Что лучше оставить в корне

В корне `fyl` лучше оставить только:
- `firmware/`
- `testbench/`
- `infra/`
- `archive/`
- `Plan/`
- `bin/`
- `tools/`
- `.gitignore`
- `fyl.code-workspace`

Это даст простой и понятный обзор рабочего пространства.

### Минимальный вариант без большого переезда

Если пока не хочется массово двигать все проекты, можно принять промежуточную структуру:

```text
fyl/
├─ conveyor_control_com10/
├─ manipulator_com11/
├─ master_control_com12/
├─ conveyor_control_com3/
├─ master_control_com9/
├─ i2c_smoketest_3boards/
├─ rs485_autodir_test/
├─ spi_linecheck_3boards/
├─ spi_smoketest_3boards/
├─ test_zapaika/
├─ infra/
├─ archive/
├─ Plan/
├─ bin/
├─ tools/
└─ ...
```

То есть:
- пока не переносить проекты прошивок по новым верхним папкам
- сначала создать только `infra`, `archive`, `tools`
- убрать из корня и из прошивочных проектов всё лишнее

Этот вариант безопаснее как первый этап.

### Рекомендуемый порядок перехода

#### Этап 1. Безопасная расчистка

- создать `infra/`
- создать `archive/`
- создать `tools/`
- перенести flash-скрипты в `tools/flash`
- перенести backup-файлы и flow-экспорты в `archive`

#### Этап 2. Инфраструктура в одном месте

- перенести `Node-RED userDir` в `infra/node-red/userdir`
- перенести рабочие конфиги `Mosquitto` в `infra/mosquitto/conf`
- подготовить локальные скрипты запуска

#### Этап 3. Глубокая уборка

- при желании разнести прошивки в `firmware/`
- при желании разнести стенды в `testbench/`
- обновить пути в workspace, скриптах и документации

### Рекомендация на сейчас

Для текущего состояния проекта я рекомендую не начинать с большого массового переноса всех прошивок.

Правильный первый шаг:
- создать `infra/`
- создать `archive/`
- создать `tools/`
- перенести туда инфраструктуру, backup и служебные скрипты

Это даст порядок в `fyl`, но почти не сломает существующие привычные пути.
