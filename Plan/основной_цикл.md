# Основной цикл линии

Дата: 2026-03-31

### Назначение

Этот документ описывает основной цикл линии.
Для базовой логики цикла он остается главным источником правды.
Для архитектурного пакета `version_4` более новые уточнения по снимкам состояния, паузе, `step3_ready` и `step7_ready` временно задаются документами `Plan/version_4/` до переноса обратно в базовый контур.

## Статус документа

- Сейчас это тестовый контур.
- В тестовом контуре `CONVEYOR` обменивается с `MANIPULATOR` напрямую по `I2C`.
- `MASTER` в тесте не участвует.
- К роли `MASTER` вернёмся после проверки прямого межплатного обмена.

## Узлы и термины

| Узел | Простыми словами | Роль в цикле |
|---|---|---|
| `INFEED` | Подводящий участок, который набирает тарелки по одной и собирает их в пары | Готовит пары тарелок |
| `SHIFT` | Каретка или узел сдвига | Переносит пару с `INFEED` на `IN2` |
| `IN2` | Подводящий накопитель перед манипулятором | Собирает блок из 6 тарелок |
| `MANIPULATOR` | Каретка с двумя синхронными блоками захватов по 6 тарелок | За один ход переносит новый блок в запайщик и, если есть, готовый блок из запайщика дальше |
| `SEALER` | Узел запайки | Запаивает блок из 6 тарелок |
| `OUT2` | Отводящий накопитель после запайщика | Принимает готовый блок и отдаёт его дальше |
| `MAIN_OUT` | Основной отводной конвейер | Уводит тарелки дальше из машины |

### О позициях `IN2` и `OUT2`

- В именах осталось слово `LINE`, но по смыслу это не отдельные ручьи, а три последовательные позиции блока.
- `IN2.LINE1..LINE3` и `OUT2.LINE1..LINE3` хранят три пары тарелок.
- Полный блок на `IN2` или `OUT2` означает:
  - `LINE1 = 1`
  - `LINE2 = 1`
  - `LINE3 = 1`

## Основной цикл

### 1. Сборка блока на `IN2`

- `INFEED` собирает тарелки в пары.
- `INFEED` может поднять пневмофлаг только когда `SHIFT = HOME_Z`.
- Перенос пары из `INFEED` в `IN2` разрешён, если одновременно выполнены условия:
  - `BUFFER_COUNT = 2`
  - `IN2.LINE1 = 0`
  - правая сторона манипулятора уже освобождена
  - в `version_4` это считаем логическим флагом `step3_ready = 1`
  - сейчас это не готовый отдельный бит из прошивки манипулятора; по одному `current step` его безопасно не выводим
- Полный цикл `SHIFT` идёт так: `HOME_Z -> BUSY -> SHIFTED_C -> BUSY -> HOME_Z`.
- `IN2` делает такт только если на `IN2.LINE1` уже стоит пара и впереди ещё есть место для сдвига.
- Если `IN2.LINE1 = 0`, `IN2` сам по себе не крутится.
- Полный блок на `IN2` означает:
  - `IN2.LINE1 = 1`
  - `IN2.LINE2 = 1`
  - `IN2.LINE3 = 1`

### 2. Когда можно запускать `MANIPULATOR`

В обычном режиме рабочий цикл манипулятора разрешён только если одновременно выполнены условия:

- на `IN2` собран полный блок
- `MANIPULATOR` не находится в `BUSY` или `ERROR`
- манипулятор в стартовом механическом положении: `право / верх / разжат`
- `SEALER = EMPTY` или `SEALER = DONE`
- если `SEALER = DONE`, то `OUT2` свободен

Если полного блока на `IN2` нет, манипулятор в обычном режиме не запускаем.

### 3. Что делает один рабочий цикл `MANIPULATOR`

- Плата конвейера даёт манипулятору только одну команду: рабочий цикл `R`.
- Отдельных команд `только загрузить` и `только выгрузить` в рабочем режиме нет.
- Оба блока захватов работают только синхронно:
  - правый переносит `IN2 -> SEALER`
  - левый переносит `SEALER -> OUT2`
- Если на одной из сторон тарелок нет, манипулятор просто делает пустое движение.

Практический смысл шагов `R` для линии:

- шаги `1..3` соответствуют захвату со стороны `IN2`
- шаги `4..6` соответствуют укладке на левую сторону
- после шага `7` блок уже уложен, вертикаль поднята, и прошивка выставляет `step7 ready`
- шаг `8` только возвращает каретку в исходное положение

Успешное завершение цикла считаем так:

- манипулятор вышел из `BUSY`
- ошибок нет
- текущий шаг снова `0`

### 4. Что меняется за один цикл

Если на `IN2` есть полный блок, а `SEALER = EMPTY`:

- происходит перенос `IN2 -> SEALER`
- на стороне `SEALER -> OUT2` идёт пустое движение
- после цикла:
  - `IN2` пуст
  - `SEALER = LOADED`

Если на `IN2` есть полный блок, `SEALER = DONE` и `OUT2` свободен:

- новый блок переносится `IN2 -> SEALER`
- готовый блок переносится `SEALER -> OUT2`
- после цикла:
  - `IN2` пуст
  - `SEALER = LOADED`
  - `OUT2` получает полный блок

### 5. Цикл запайки

Если после рабочего цикла в `SEALER` уложен новый блок:

- `CONVEYOR` запускает запайщик
- состояния идут так: `LOADED -> RUNNING -> DONE`
- следующий рабочий цикл манипулятора в обычном режиме разрешён только после `SEALER = DONE`

Если нужна ранняя синхронизация, можно ориентироваться на `step7 ready`, а не ждать полного возврата манипулятора домой.

При этом в текущей прошивке `step7 ready` ведет себя как latch:

- после достижения шага `7` он поднимается
- держится до старта следующего цикла `R`
- для ранней синхронизации его безопасно использовать как переход `0 -> 1` внутри уже наблюдаемого рабочего цикла, а не как любое чтение `1`

### 6. Отвод из `OUT2` на `MAIN_OUT`

- `OUT2` начинает отдачу, если хотя бы одна из его линий занята и `MAIN_OUT = EMPTY`
- после первого такта освобождается `OUT2.LINE1`
- после второго такта освобождается `OUT2.LINE2`
- после третьего такта освобождается `OUT2.LINE3`
- если `MAIN_OUT` занят, следующий такт ждёт

### 7. Поведение при команде паузы

При паузе система не должна останавливаться в случайной точке.

Если последний блок на подводящей стороне ещё собирается:

- `INFEED`, `SHIFT` и `IN2` продолжают работать по обычным условиям
- если тарелок до полного блока не хватает, подвод продолжает крутиться
- оператору показываем сообщение: `добавьте еще N тарелок`
- после сборки полного блока:
  - даём один цикл `MANIPULATOR`
  - дожидаемся завершения запайки
  - даём ещё один цикл, чтобы убрать готовый блок из `SEALER`

Если последний блок на подводящей стороне уже не собираем, но в `SEALER` есть готовый блок:

- проверяем, что `OUT2` свободен
- разрешаем один цикл только ради выгрузки из `SEALER`
- со стороны `IN2` это будет пустое движение
- после этого запайщик заново не запускаем

Если и на подводящей стороне, и в `SEALER` пусто:

- дополнительных циклов перед паузой не требуется

## Связь с прошивкой и `I2C`

- обычная производственная команда манипулятору это `R`
- сервисное восстановление это отдельная команда `V`
- recovery не считаем обычным производственным шагом линии
- для цикла `CONVEYOR` достаточно опрашивать:
  - `IDLE / BUSY / ERROR`
  - текущий шаг `0..8`
  - признак `step7 ready`
- отдельного бита `step3 ready` на `I2C` сейчас нет
- цикл считаем завершённым, когда получаем:
  - `mode = IDLE`
  - `step = 0`
  - ошибок нет
